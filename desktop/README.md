# Agon for Windows

The same client as the Android app, as a Windows program: one window showing arena.ai in a
persistent session, with the app's own menu, downloads and updates. Unofficial — see
`../NOTICE.md`.

## Build and run

Needs **Node.js 18+** (nothing else; the Android SDK is not involved).

One command from the repository root builds this **and** the APK:

```bat
build-all.bat
```

It copies `Agon-Setup-<version>-{x64,ia32}.exe` and
`Agon-Portable-<version>-{x64,ia32}.exe` into the repository root, next to the APK.

To work on just the desktop app:

```bat
cd desktop
npm install
npm run icon      :: optional - regenerates build\icon.ico from ..\artwork\agon-mark.jpg
npm start         :: run it from source
npm run dist      :: build the installers into desktop\release\
```

`npm run dist` produces, for **both 64-bit and 32-bit Windows**:

| File | What it is |
| --- | --- |
| `Agon.exe` | the 64-bit installer under its short name (`build-all.bat` makes this copy for you) |
| `Agon-32.exe` | the 32-bit installer under its short name |
| `Agon-Setup-<version>-x64.exe` | 64-bit installer (per-user, choose the folder) |
| `Agon-Setup-<version>-ia32.exe` | **32-bit** installer, for old Windows on old hardware |
| `Agon-Portable-<version>-x64.exe` / `-ia32.exe` | no install, runs from anywhere |
| `latest.yml` + `.blockmap` | what the auto-updater reads |

All four installers appear because the scripts pass `--x64 --ia32` explicitly. Naming targets
on the command line (`--win nsis portable`) without arch flags makes electron-builder ignore
the `arch` lists in `build.win.target` and build for the host architecture only — that is how
a release can end up with no 32-bit `.exe` at all, which is what happened to `v1.4.24`.
`build-all.bat release`, `npm run dist` and CI all go through the same script, so the fix
applies everywhere.

### Setup vs Portable - what actually differs

Same app, same binaries, same release; the only difference is **where it lives and what it
writes**, plus whether an uninstaller exists.

| | `Agon-Setup-<ver>-x64.exe` (= `Agon.exe`) | `Agon-Portable-<ver>-x64.exe` |
| --- | --- | --- |
| Install step | NSIS wizard: choose the folder, per-user (no admin prompt, `asInvoker`) | none - it runs where it is |
| Where the app files go | `%LOCALAPPDATA%\Programs\Agon\` | a temp folder unpacked on every launch from the single `.exe` |
| Start Menu / desktop shortcut | yes, named **Agon**, points at the installed copy | no |
| Add/Remove Programs entry + uninstaller | yes | no - delete the `.exe` |
| Where the session lives (cookies, cache, window size) | `%APPDATA%\Agon` | `Agon-data\` **next to the .exe** (falls back to `%APPDATA%\Agon` if that folder is read-only) |
| Startup time | faster - nothing to unpack | a few seconds slower on each launch |
| Portable on a USB stick, keeps you signed in | no (that PC keeps the session) | yes, the session travels with the stick |
| Auto-update | yes (`latest.yml`) | yes, but it rewrites the file it was started from - keep it on a writable stick |
| Best for | your own PC | a friend's PC, a lab machine, a USB stick |

Neither one is signed with a paid certificate, so SmartScreen shows "unrecognised app" on the
first run of both - *More info* → *Run anyway*.

### If packaging fails

**`Cannot create symbolic link … darwin\10.12\lib\libcrypto.dylib` (error exit status 2).**
electron-builder downloads a 5.6 MB `winCodeSign` archive to *rename and sign* the exe, and
that archive contains **macOS symlinks**. Windows only lets you create a symlink with
Administrator rights or Developer Mode, so the unpack fails, retries four times and the build
dies. `win.signAndEditExecutable: false` (the default here) skips that code path entirely:
`winPackager.signApp()` returns before it ever asks for the bundle. Two ways out:

| | Command | What it costs |
| --- | --- | --- |
| **Default (works for everyone)** | `npm run dist` (or `build-all.bat`) | Builds unprivileged. Windows skips resource editing, so the **`.exe` file itself keeps Electron's icon** — the window/taskbar icon is still Agon's, and the Start Menu entry is named Agon. |
| **Branded `.exe`** | `npm run dist:branded` | Needs **Developer Mode on** (Settings → System → For developers) or an Administrator terminal. Then the exe, shortcut and taskbar all carry the Agon mark. |

If an old half-extracted cache still breaks even the default build, delete
`%LOCALAPPDATA%\electron-builder\Cache` and run it again.

**`default Electron icon is used`.** `desktop/build/icon.ico` and `icon.png` were missing
(they are committed, and regenerated by `npm run icon`). Packaging now fails outright if
either is absent, instead of quietly shipping Electron's logo.

`ia32` is not decoration: it is the build that runs on a 32-bit Windows install, and it is
why the target list names both architectures explicitly. (Electron 26 is the last line that
still ships 32-bit Windows binaries, which is why the dependency is pinned to it.)

## Updates

The Windows build updates itself from **this repository's own GitHub releases**, the same
release the APK lives in — `tools/publish.ps1` builds both for one tag, so the version
number on the phone and on the PC always match.

- Checks 20 seconds after launch, then every 6 hours, and on demand from
  *Agon → Check for updates…*.
- `electron-updater` verifies the download against the SHA-512 in the release's
  `latest.yml` before it is offered. Nothing installs silently: it asks, then restarts.
- A private repository needs a token. Set `GH_TOKEN` before launching `npm run dist`
  (read-only *Contents* is enough to download; the upload needs the write token that
  `publish.bat` already uses).

## What it does and does not do

- One window, no Node in the page (context isolation on, sandbox on, no `<webview>`).
- Only `https://arena.ai` / `lmarena.ai` may load in the window; a provider popup
  (Google) gets a child window in the same session so the cookie still lands in Arena,
  and every other link is refused.
- Downloads go to the user's Downloads folder with the name flattened to one path segment.
- No camera, microphone, location, clipboard-read or notification permission is granted:
  the permission handler allows only fullscreen and a sanitized clipboard write.
- Devtools only when `AGON_DEVTOOLS=1` is set, or from *View → Toggle developer tools*.

## Status of the other platforms

- **Android** — this repository's main app, `app/`.
- **Windows** — this folder.
- **iOS** — not buildable from this repository, and not for lack of an icon: an iOS build
  needs a Mac, Xcode, and a `WKWebView` app plus its own signing profile. The equivalent
  client would be a small Swift shell around `WKWebView` with the same host allow-list;
  it is a separate project, and it is deliberately not a stub here so nobody downloads a
  file that cannot run.
- **macOS / Linux** — dropped: the scope is Android, iOS and Windows.
